# Synara research: features and merged PRs worth taking

Researched 2026-11-12. Tracking: [Solenta #1999](https://github.com/currentbits/solenta/issues/1999).

Follow-up: the requested iOS simulator implementation is now adapted and live-tested;
see the [adoption report](2026-11-12-synara-ios-simulator.md) and [#2000](https://github.com/currentbits/solenta/issues/2000).

## Recommendation

Take **continuous browser annotations**, **usage totals for CLI sessions outside Solenta**, and **page-declared WebMCP tools**. Add **chat-authored MCP setup proposals** after those. A draft excerpt is a small polish opportunity. Linux ARM64 desktop packaging is conditional on demand.

The highest immediate reliability return is to add Synara's concrete failure scenarios to Solenta's existing investigations. Do not turn every upstream fix into a new feature or assume Solenta has the same bug.

## Feature shortlist

Effort is a relative engineering judgment, not an implementation estimate.

| Order | Take | Why it helps | Smallest useful Solenta version | Effort / status |
| --- | --- | --- | --- | --- |
| 1 | Continuous browser annotations | Give several precise UI corrections in one pass. | Keep Inspect active, collect numbered elements plus comments, and send through existing element chips. | Medium; partial building blocks already exist. |
| 2 | External CLI-session usage | Show work done from Terminal as well as inside Solenta. | Add an explicit local-session scope for Claude/Codex to the existing Usage view; preserve source and deduplicate. | Medium–large; new scope. |
| 3 | WebMCP discovery and invocation | Use a page's declared actions instead of guessing DOM interactions. | Two bounded, document-scoped actions on the existing preview/MCP surface, initially for loopback pages. | Large; new capability. |
| 4 | MCP setup proposals in chat | Let an agent prepare an exact connector configuration for the user to review. | Pending add/remove/import proposal using the existing server registry, guards, and owner-computer approval. | Medium; management already exists, proposal flow does not. |
| 5 | Unsent-draft excerpt | Find unfinished prompts without opening every thread. | Show a short saved-draft excerpt on the existing draft marker's accessible tooltip/popover. | Small; marker already exists. |
| 6 | Linux ARM64 desktop packages | Serve ARM Linux workstations. | Native ARM64 packaging and startup qualification, with architecture-safe update selection. | Medium–large; only if users need the desktop target. |

### 1. Continuous browser annotations

Synara [#456](https://github.com/Emanuele-web04/synara/pull/456) adds repeated element capture, comments, draft persistence, and numbered markers. [#507](https://github.com/Emanuele-web04/synara/pull/507) improves the picker and batches layout reads before writes. Current [useBrowserAnnotations.ts](https://github.com/Emanuele-web04/synara/blob/83e0533b23099908ee14e4fecacd5ed702f4d453/apps/web/src/components/browser/useBrowserAnnotations.ts) retains an active annotation session and rejects stale start results by thread, tab, and request identity.

Solenta already has single-element Inspect, keyboard operation, cropped screenshots, comments, and persisted `element` chips. The gap is the continuous interaction and marker projection, not precise element context itself. See [BrowserPane.tsx](https://github.com/currentbits/solenta/blob/d66e192c84ebaa06ded4ca725e0bf5039f94e462/src/components/BrowserPane.tsx) and [contextChips.ts](https://github.com/currentbits/solenta/blob/d66e192c84ebaa06ded4ca725e0bf5039f94e462/src/contextChips.ts).

Reuse those chips and their current serializer. Keep captured evidence frozen; do not silently re-resolve an old selector against a new document. Scope live markers to the thread and document; preserve the existing treatment of page content as untrusted data. Require real user interaction for page-overlay controls and preserve keyboard access.

Change reach: `electron/preview.js`, Browser pane, typed preview contracts/IPC bridges, element-chip draft/transcript rendering, and preview/composer tests. Do not create another attachment format. [#1891](https://github.com/currentbits/solenta/issues/1891) covers dictating comments; continuous annotation is a separate interaction improvement that should cooperate with it.

Acceptance: capture three elements without re-entering Inspect; review/remove their comments; survive a thread switch/reload without cross-thread delivery; invalidate live markers after navigation; reject synthetic page-generated input.

### 2. External CLI-session usage

Synara [#2109](https://github.com/Emanuele-web04/synara/pull/2109) adds separate in-app and local-session analytics scopes. It replaces overlapping Claude/Codex application rows in the wider scope, deduplicates responses across fork/resume history, and labels API-rate cost rather than implying subscription charges.

The implementation is useful reading: [transcriptUsage.ts](https://github.com/Emanuele-web04/synara/blob/83e0533b23099908ee14e4fecacd5ed702f4d453/apps/server/src/transcriptUsage.ts) streams session files and caches unchanged/grown files; [usageAnalyticsStats.ts](https://github.com/Emanuele-web04/synara/blob/83e0533b23099908ee14e4fecacd5ed702f4d453/apps/server/src/usageAnalyticsStats.ts) separates application and session-file sources. These are source-level observations, not a benchmark reproduced here.

Solenta already has daily/provider/model/project/thread usage and CLI transcript imports. Its [Usage view](https://github.com/currentbits/solenta/blob/d66e192c84ebaa06ded4ca725e0bf5039f94e462/src/components/UsageView.tsx) reads its own ledger; [cli-sessions.js](https://github.com/currentbits/solenta/blob/d66e192c84ebaa06ded4ca725e0bf5039f94e462/electron/cli-sessions.js) supplies provider-home discovery and import infrastructure. Importing conversations is not the same as offering a usage-only aggregate.

Reuse discovery and home/account selection. Extract usage without creating threads or importing prompt text into the usage store. Keep historical external totals out of today's spend-cap ledger. Preserve unknown/unpriced values, show provenance, and test resumed/forked/subagent duplicates. Keep Solenta's current verified Claude accounting rules: do not replace them with Synara's first-resume-result baseline shortcut.

Change reach: CLI discovery/parsers, usage aggregation/query contracts, Usage controls, account/host ownership, and usage fixtures. Initial scope should be explicitly selected local Claude/Codex homes. Additional providers, automatic remote crawling, a new dashboard, and a dynamic pricing service are unnecessary for the first version.

Acceptance: the same response in an imported thread, original session, and fork counts once; incremental appends count once; rewritten/truncated files are re-read safely; missing files are reported as incomplete coverage.

### 3. WebMCP

Synara [#808](https://github.com/Emanuele-web04/synara/pull/808) introduced provider-neutral discovery and stale-safe calls with bounded schemas/results. **Its original tool names are historical:** current [browserAutomationCatalogue.ts](https://github.com/Emanuele-web04/synara/blob/83e0533b23099908ee14e4fecacd5ed702f4d453/packages/shared/src/browserAutomationCatalogue.ts) exposes `webmcp.tools/invoke` through `browser_run`. The current [guest bridge](https://github.com/Emanuele-web04/synara/blob/83e0533b23099908ee14e4fecacd5ed702f4d453/apps/desktop/src/browserWebMcp/guestBridge.ts) validates secure contexts, tool policy, schemas, and output size.

Solenta has snapshot/click/type/diagnostics/Inspect, but no WebMCP integration was found in the inspected newer main. Implement discovery and invocation in its existing preview tool rather than importing Synara's BetterWright browser runtime. Start with the existing loopback-only boundary.

Discover only on demand. Bind a discovered tool to a document generation and descriptor; refuse calls after navigation or descriptor changes. Treat names, descriptions, schemas, and results as untrusted. Page declarations and a read-only hint cannot authorize a mutation. Preserve cancellation and the user's existing permission boundaries.

Change reach: guest bridge, preview host, preview tool schema/dispatcher, typed IPC, and adversarial guest tests. Test a local page registering one read and one mutation, stale discovery after navigation, cancellation, oversized schema/result, and policy denial. This is not the same feature as interactive MCP Apps ([#1935](https://github.com/currentbits/solenta/issues/1935)).

### 4–6. Secondary work

- **MCP proposals:** Synara [#2049](https://github.com/Emanuele-web04/synara/pull/2049) makes agent-requested configuration inert until the owning computer's UI approves it. The [proposal card](https://github.com/Emanuele-web04/synara/blob/83e0533b23099908ee14e4fecacd5ed702f4d453/apps/web/src/components/settings/McpConnectorProposalCard.tsx) separates Review from Approve. Solenta already has stdio/HTTP configuration, imports, OAuth, tool policy, and guardrails in `mcp.js`, `ipc-mcp.js`, and `McpMarketplace.tsx`. Add only the proposal lifecycle and review card; show command/args/cwd/env keys while keeping secret values hidden. Reject approvals after the proposal's owner or configuration changes.
- **Draft excerpts:** Synara [#1579](https://github.com/Emanuele-web04/synara/pull/1579) previews the real saved draft, including while prompt history is being browsed. Solenta's newer `ThreadCard.tsx` already has a subscribed unsent-draft marker ([#1770](https://github.com/currentbits/solenta/issues/1770)), but only its generic label. Reuse that subscription and the saved draft; do not expose transient history text or raw context placeholders. Keep the full draft unchanged.
- **Linux ARM64:** Synara [#2110](https://github.com/Emanuele-web04/synara/pull/2110) adds native packages and architecture-specific feeds. Solenta's inspected `scripts/package-cross.sh` still targets Linux x64/Windows x64. Remote ARM host support and desktop ARM packaging are different products. Qualify native dependencies, startup, and correct update payload before adding a download. Do not copy the AppImage packaging model automatically.

## What to skip

- **A browser rewrite or credential vault.** [#1114](https://github.com/Emanuele-web04/synara/pull/1114) adds a substantial embedded runtime, saved-logins vault, session restore, and popup machinery. Solenta's loopback preview serves a narrower purpose. Adopt the specific interaction feature before considering a new browser product.
- **Bundled native Computer Use as a quick parity item.** [#1090](https://github.com/Emanuele-web04/synara/pull/1090) involves platform drivers, ownership leases, focus restoration, cancellation, and permissions. Solenta's headless CLI does not gain desktop control from a permission-mode switch.
- **Cloud subscription/profile/recap infrastructure.** [#1412](https://github.com/Emanuele-web04/synara/pull/1412) combines remote connections with private account history. Take host-ownership principles; account billing, public profiles and a hosted inbox are separate product decisions.
- **Every provider integration.** Synara has additional providers including Pi, Droid and Antigravity. Add one only when requested or justified by users, through Solenta's existing adapter boundary. More providers alone are not an adoption strategy.
- **Language expansion based on an old merged PR.** [#2014](https://github.com/Emanuele-web04/synara/pull/2014) introduced localization, but [#2083](https://github.com/Emanuele-web04/synara/pull/2083) returned the interface to English. The latest changelog/source matters.
- **Synara-specific SQLite migration and cloud deployment machinery.** Its storage and service architecture differ from Solenta's JSON/shard store plus memory SQLite. Backup and uncertain-delivery principles transfer; migration numbers and SQL repairs do not.

## Follow-through and limits

Three new-work chips accompany this research: continuous annotations, external-session usage, and WebMCP. The research issue is completed separately from those unimplemented features. Existing #1905, #1910 and #1913 received narrowly scoped source evidence rather than duplicate implementation tickets.

No app/runtime tests, live-provider trials, installed-app upgrades, physical simulator tests, or performance benchmarks were run. The artifacts are documentation and a metadata index. Source inspection supports the proposed gaps and deduplication; a PR merge or an author's test report does not establish a reproduced Solenta bug.
