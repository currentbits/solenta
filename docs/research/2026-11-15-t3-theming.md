# T3 Code's theming engine and a Solenta adoption path

Tracking: [#2032](https://github.com/currentbits/solenta/issues/2032). Researched November 15, 2026 against T3 main [32c069ee](https://github.com/pingdotgg/t3code/tree/32c069eed1d22ca4b4bbaa52ec8d34bb3f4a9ff3), following [#35247](https://github.com/pingdotgg/t3code/pull/35247) and [#36656](https://github.com/pingdotgg/t3code/pull/36656). Source research only; no upstream writes or theming implementation.

## Recommendation

Take the **palette model, live preview/revert, and JSON import/export** first. Solenta already uses semantic CSS variables, so this can extend its existing theme switch without importing T3's application framework. Add user-editable CSS and agent-published themes only as a separate feature with explicit review and a recovery control outside the themed DOM.

T3 has a complete appearance system rather than a single stylesheet: semantic color roles, generated palettes, custom theme storage, an editor, a server publication layer, and agent tools. Most of that is useful design reference; its React/Effect state machinery is not something Solenta needs to copy.

Appearance and palette selection are separate: a client can follow the OS while selecting different light and dark themes. Palette generation aims for readable defaults, but arbitrary overrides or CSS can defeat contrast; generated colors do not establish accessibility for every final theme. The user guide also describes T3/VS Code imports. The VS Code conversion path was not audited in this refresh. [Palette source](https://github.com/pingdotgg/t3code/blob/32c069eed1d22ca4b4bbaa52ec8d34bb3f4a9ff3/apps/web/src/themePalette.ts), [guide](https://github.com/pingdotgg/t3code/blob/32c069eed1d22ca4b4bbaa52ec8d34bb3f4a9ff3/docs/user/appearance.md).

## Publication and client ownership

The server accepts either exported theme data or a shorter canvas/accent definition with optional role overrides. IDs cannot shadow reserved/built-in names. Publication stages a file, renames it atomically, checks that it became publishable, and restores the prior file if selecting it fails. Reads reject symlinks/non-files and bound individual and aggregate input size; scanning examines at most 32 candidate files. Changes are debounced and refresh/publication operations are serialized. [Environment service](https://github.com/pingdotgg/t3code/blob/32c069eed1d22ca4b4bbaa52ec8d34bb3f4a9ff3/apps/server/src/environmentTheme.ts).

At this snapshot CSS is limited to **50,000 characters**. The file cap derives from the worst-case JSON escape expansion: **316,384 bytes per file**, with a **1,898,304-byte aggregate cap**. These are separate limits: accepting a string in the schema does not mean its encoded file will fit unless both limits agree. [Contract](https://github.com/pingdotgg/t3code/blob/32c069eed1d22ca4b4bbaa52ec8d34bb3f4a9ff3/packages/contracts/src/server.ts#L625), [#36656](https://github.com/pingdotgg/t3code/pull/36656).

A published default is adopted once per environment and update generation. Clients wait until its definition resolves before recording adoption, and subsequent local choices persist until the server sets a newer generation. Theme and appearance have independent generations. This prevents a recurring server update from overwriting a later local preference. [useDefaultTheme.ts](https://github.com/pingdotgg/t3code/blob/32c069eed1d22ca4b4bbaa52ec8d34bb3f4a9ff3/apps/web/src/hooks/useDefaultTheme.ts).

## CSS and agent safety

T3 treats theme CSS as potentially hostile. A stylesheet can conditionally request URLs based on DOM attributes, leaking information without JavaScript. Its server text check gives early feedback, while the browser parses the stylesheet and removes fetch-capable declarations/rules. Constructed stylesheets disallow imports; normalized declaration checks reject nonlocal URLs, string-based image fetching, and unresolved backslash escapes. Allowed local/data references remain possible. Unknown rule shapes are dropped unless the walker can inspect them; nested rules, keyframes, and registered properties receive special handling. [Shared checks](https://github.com/pingdotgg/t3code/blob/32c069eed1d22ca4b4bbaa52ec8d34bb3f4a9ff3/packages/shared/src/themeCss.ts), [CSSOM application](https://github.com/pingdotgg/t3code/blob/32c069eed1d22ca4b4bbaa52ec8d34bb3f4a9ff3/apps/web/src/themeCss.ts).

The authoring guide exposes stable `data-*` selectors rather than relying on utility classes. That is a useful compatibility contract, but it still gives themes substantial control over layout and visibility. Fetch filtering does not stop CSS hiding approval buttons, making text unreadable, or consuming excessive rendering time. [Guide and selector hooks](https://github.com/pingdotgg/t3code/blob/32c069eed1d22ca4b4bbaa52ec8d34bb3f4a9ff3/packages/shared/src/themeCss.ts).

Agent writes require the environment-write access policy and recheck access after waiting for the thread lock. Linked callers are refused by default. The code allows the policy's live full-access/default caller modes or a qualifying full-access client; the user guide describes the simpler Full access workflow. Neither the tool's presence nor its annotations alone authorize a write. [McpToolAccess.ts](https://github.com/pingdotgg/t3code/blob/32c069eed1d22ca4b4bbaa52ec8d34bb3f4a9ff3/apps/server/src/mcp/McpToolAccess.ts#L319), [theme handler](https://github.com/pingdotgg/t3code/blob/32c069eed1d22ca4b4bbaa52ec8d34bb3f4a9ff3/apps/server/src/mcp/toolkits/theme/handlers.ts).

These observations are not a security certification. Before shipping CSS in Solenta, reproduce adversarial cases on its actual Electron Chromium version: escaped function names, custom properties, nested/new at-rules, data/SVG resources, font sources, and attempts to hide the recovery UI. Mobile uses its own appearance system in T3; web/desktop custom-theme support should not be mistaken for mobile parity. [Appearance guide](https://github.com/pingdotgg/t3code/blob/32c069eed1d22ca4b4bbaa52ec8d34bb3f4a9ff3/docs/user/appearance.md).

## Fit with Solenta

Solenta currently has System/Light/Dark selection, a first-paint storage cache, semantic variables, native-window appearance, syntax styling, and terminal colors derived from app variables. Its `settings.theme` union represents appearance, not a custom theme identity. Reusing that field for arbitrary IDs would break assumptions in the renderer and native-window path. Sources: [theme.ts](../../src/theme.ts), [index.css](../../src/index.css), [GeneralPane](../../src/components/settings/GeneralPane.tsx), [native application](../../electron/main.js), [TerminalPane](../../src/components/TerminalPane.tsx).

| Stage | Smallest useful addition | Keep out of that stage |
| --- | --- | --- |
| 1. Palettes | A versioned semantic-color definition; separate palette ID and appearance; a few presets; bounded validated JSON import/export; live preview with Cancel restoring the old theme. | Arbitrary CSS, per-project themes, remote publication, a new state-management framework. |
| 2. Editor | Canvas/accent editing with derived semantic colors and contrast checks, then explicit advanced overrides. Reuse existing settings controls. | A general stylesheet IDE or a full VS Code theme converter before demand is established. |
| 3. Optional CSS | Stable styling hooks, CSSOM fetch filtering, payload bounds, and a native/menu reset that custom CSS cannot hide. | Assuming a regex or CSP alone makes arbitrary styles safe. |
| 4. Optional agents | Read-only theme discovery/guide plus an inert proposed-theme preview that the owning user can apply or discard. Preserve local choices and scope changes to the owning computer. | Silent machine-wide restyling from a thread, automatic acceptance of imported CSS, or remote agents overriding another client's preference. |

The first stage can reuse the current tokens and theme application. Broader terminal/editor/diff color coverage needs explicit adapters where surfaces are not ordinary DOM/CSS. This is an adoption recommendation, not authorization to build these additional theming stages.

## Evidence limits

Read the referenced contracts, palette generation/application and storage, editor preview lifecycle, environment publication, CSS filtering, default adoption, and agent access paths at the pinned revision. No T3 instance was launched, imports were not round-tripped, and performance, visual quality, contrast across all themes, and sanitizer resistance were not independently tested.
