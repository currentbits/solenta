## Recommendation

Start with **recovering from a failed login-shell PATH probe** and **retrying failed terminal resizes**. Both have direct counterparts in current Solenta source. Next, investigate **Claude plan reporting on newer models** and extend **typed skill delivery**. Keep checkpoint safety and image ordering under their existing investigations rather than creating competing projects.

This is research, not an implementation batch. No application behavior changed and no upstream comments, reviews, reactions, or issues were posted.

### 1. Failed shell probes must be recoverable

T3 [#30667](https://github.com/pingdotgg/t3code/pull/30667) adds bounded background rediscovery after startup shell discovery fails, including a Mac asleep during launch. Its patch separates startup and retry budgets and stops after success or a bounded attempt count.

Solenta's [refreshLoginPath](https://github.com/currentbits/solenta/blob/82a774fdb1da42c94ed3c158e0f51b176bf9af97/electron/pathEnv.js#L365) sets `refreshed = true` even on failure and retains `refreshing`; subsequent calls return that same promise. The noisy-output/fish fix in #2020 improved parsing but did not add recovery. Fallback directories and a prior cache reduce the impact; the gap matters when the missing provider lives only in the uncaptured shell PATH. This is source-confirmed behavior, not a reproduced idle-Mac failure in Solenta.

Acceptance: fail the first capture, let a later capture succeed without relaunching, then discover and start the provider. Deduplicate concurrent retry requests, preserve unrelated environment changes, stop timers on shutdown, and avoid retrying successful probes. Do not import T3's framework or copy its timeout values without justification.

### 2 and 5. Terminal size and replay correctness

T3 [#32047](https://github.com/pingdotgg/t3code/pull/32047) retries a failed resize once, using the current grid and session generation so an older retry cannot overwrite a newer resize. Solenta's [resize callback](https://github.com/currentbits/solenta/blob/82a774fdb1da42c94ed3c158e0f51b176bf9af97/src/components/TerminalPane.tsx#L297) ignores both return values and errors. The [backend](https://github.com/currentbits/solenta/blob/82a774fdb1da42c94ed3c158e0f51b176bf9af97/electron/terminal.js#L574) catches PTY exceptions and returns `{ok:false}`. Handling promise rejection alone would miss this failure path.

Acceptance: fail one resize with an otherwise healthy connection; the PTY eventually receives the pane's latest size without another drag. A retry from a closed/reopened terminal or older grid must not win. Keep retries bounded.

T3 [#36368](https://github.com/pingdotgg/t3code/pull/36368) tracks control-sequence state through scrollback trimming and skips a retained fragment when replaying into a fresh emulator. Solenta's [terminal buffer](https://github.com/currentbits/solenta/blob/82a774fdb1da42c94ed3c158e0f51b176bf9af97/electron/terminal.js#L119) can cut at an arbitrary character cap, or at a newline inside a long OSC/DCS sequence. A reopened emulator then lacks the parser context that preceded the retained suffix. #2022 prevents replies to restored queries being written into the shell; it does not establish a safe replay boundary.

Acceptance: trim inside split CSI/OSC/DCS sequences, including across chunks and restarts; replay clean visible output without printing fragments or swallowing later text. Keep cursor offsets consistent and preserve #2022's muted input during replay. Solenta already batches output at 16 ms, so T3 [#37060](https://github.com/pingdotgg/t3code/pull/37060)'s 2 ms batching is not a missing feature; its Windows measurements do not establish a Solenta speedup.

### 3. Claude turn-plan reporting

Synara [#2140](https://github.com/Emanuele-web04/synara/pull/2140) reports that newer Claude models no longer receive the native task-list tools. It adds an always-loaded Claude-only `update_plan` MCP tool, validates the full checklist, requires an active turn, and feeds accepted calls into the existing task UI. The author reports live Opus 5.5 use, but that observation was not independently repeated here.

Solenta's [Claude adapter](https://github.com/currentbits/solenta/blob/82a774fdb1da42c94ed3c158e0f51b176bf9af97/electron/runner-provider-claude.js#L274) mirrors `TodoWrite`; [savePlanSteps](https://github.com/currentbits/solenta/blob/82a774fdb1da42c94ed3c158e0f51b176bf9af97/electron/runner.js#L1432) already updates the thread checklist. The orchestration MCP catalog has crew tasks and Planboard issues, which serve different purposes; a per-turn checklist should reuse `planSteps`, not create one issue per step.

First reproduce a multi-step task with the installed Claude CLI/model. If needed, add a narrowly scoped tool with bounded content, owner/run identity checks, and acknowledgement before changing visible state. Preserve interrupted/failed steps and legacy `TodoWrite`. Do not copy automatic completion of every open step at normal turn end without deciding whether it accurately represents unfinished work. An always-loaded tool adds prompt overhead and still cannot guarantee model use.

### 4. Typed and shared skills

Synara [#2142](https://github.com/Emanuele-web04/synara/pull/2142) resolves typed `/name` and `$name` alongside menu selections. It selects enabled skills from the active provider's catalog, inlines instructions when native dispatch would fail, and excludes agent-origin messages and goal continuations. Its patch computes native-vs-inline delivery from the final assembled prompt.

Solenta already handles the leading-slash/headless problem: [runner dispatch](https://github.com/currentbits/solenta/blob/82a774fdb1da42c94ed3c158e0f51b176bf9af97/electron/runner.js#L2360) calls [expandInvocableCommand](https://github.com/currentbits/solenta/blob/82a774fdb1da42c94ed3c158e0f51b176bf9af97/electron/cliCommands.js#L380), preserves the raw transcript, and keeps a leading command ahead of the hand-off prefix. Rebuilding that path is unnecessary. The incremental gap is multiple or mid-sentence references and cross-provider resolution beyond the existing provider-plus-`.agents` catalog view. Native CLIs may resolve some plain-text references themselves; absence of host expansion is not proof that every such invocation fails.

Acceptance: leading, mid-sentence, punctuation-adjacent, and multiple skill references; duplicate names; disabled/non-invocable skills; missing files; live steers and resumed turns. Resolve only explicit user invocation, respect reserved commands, avoid scanning quoted history or notices, deduplicate loaded files, and bound prompt expansion. Keep project/provider precedence intact.

### 6. Failed folder navigation

Synara [#2129](https://github.com/Emanuele-web04/synara/pull/2129) retains the last readable folder after a navigation error. Solenta's [PathBrowser](https://github.com/currentbits/solenta/blob/82a774fdb1da42c94ed3c158e0f51b176bf9af97/src/components/PathBrowser.tsx#L130) clears its listing and its error branch replaces all navigation rows. Users can still type a new path; this is a recovery/usability gap, not a complete deadlock.

Acceptance: browse a readable parent, fail opening a child, then navigate/select a readable folder without reopening the dialog. Reset saved listings when the environment changes; do not present one host's entries under another host's path. Preserve stale-response cancellation and make the error visible alongside usable controls.

## Follow-through and limits

The first implementation batch should stay narrow: PATH recovery and terminal resize recovery, each with a deterministic failure/recovery test. Validate Claude plan reporting next, then choose skill invocation or safe terminal replay based on the observed user impact. Do not start an app-wide performance rewrite from upstream benchmark numbers.

Keep the earlier deferred list on #2018 intact: model mentions, opening a subagent beside its parent, screen-reader announcements, streamed Claude history import, and remaining Git/PR/Unicode edge cases. This refresh neither completes that roadmap nor authorizes implementation.

Research validation checks inventory totals, uniqueness, merge-window membership, source URLs, and report/inventory consistency. Runtime tests, full upstream diff audits, live provider checks, benchmark reproduction, and packaged cross-platform qualification remain undone. The main risk is treating an analogous upstream symptom as an already reproduced Solenta defect; this report distinguishes source gaps from investigations for that reason.
