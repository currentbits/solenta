# Whole-app performance, before vs after #1475 — 2026-10-06 (PM3)

This is a measurement only; no product code changed. It compares two commits:
- **BEFORE** `a1c696aa`: main just before the first #1475 fix.
- **AFTER** `8b4bcc71`: main after #1478–#1486, the same tree as `nightly-202610060729-8b4bcc71`.

Both commits were measured in the same session, on the same frozen copy of today's data, using the PM1 and PM2 scenarios. The data:
- a 6.06 MB envelope;
- 2,099 threads (1,139 archived) in 14 projects;
- 2,099 message shards totalling 790 MB.

The 10-05 reports (`2026-10-05-main-process.md`, `2026-10-05-renderer.md`) used a different machine state and a smaller store, so their numbers are context only.

**Didn't move, or got worse:**
- **Big-thread switch:** 160 → 147 ms on the 3.3 MB thread (−8%). PM2 expected ~100 ms, and it's still one ~135 ms long frame.
- **More pushes while streaming:** `thread:updated` pushes and `Store.save()` calls went up ~10% during a stream (152 → 167). This is harmless, because saves no longer rewrite the envelope.
- **Soak RSS still climbs:** heap and RSS rise over the soak (heap 40.8 → 52.7 MB, RSS peak 416 MB), even though DOM nodes are now bounded.
- **Main-heap cap is per thread, not per byte:** opening the 10 largest threads still adds ~32 MB of heap. The LRU caps hydrated transcripts at 8 threads, not at a byte budget.
- **Boot reads about as many bytes as before:** AFTER still reads both side files in full at boot (`thread-notes.json` 2.26 MB, `usage-threads.json` 0.79 MB). Boot read bytes fell only 14% (13.9 → 11.9 MB). Load wall time still halved, because work logs now hydrate lazily.
- **Unchanged (already fine before):**
  - `threads.get` round trip for a big thread (24 ms);
  - idle CPU (13 ms of JS per 30 s);
  - small-thread switches (23–33 ms);
  - the select → last-path-answer span on the first big-thread open (~155 ms, bounded by rendering, not IPC).

## Method

Everything ran from scratch scripts in `/tmp/perf3/` (not committed). It follows PM1's recipe, with the PM2 renderer scripts ported to it.

**Builds.**
- Both commits were exported with `git archive` into `/tmp/perf3/{before,after}`, so the real repo's worktree list was untouched.
- `node_modules` were APFS clones from the main checkout. Lockfiles were identical across all three trees apart from the version bump.
- Each tree got `core` built and `npx vite build` run, then launched with `CODER_PROD=1`.

**Data.**
- One frozen snapshot of `~/Library/Application Support/Solenta`, taken at 09:58, without `worktrees/` and without `memory-server.json`, `orch-server.json` and `mcp-coder-memory.json`.
- All 81 live-dir paths in the store and its `.bak` were rewritten to `/tmp/perf3/data`; that includes the 64 `worktreePath`s and the scratch project.
- Each build got its own fresh `cp -Rc` of that snapshot. It was moved onto `/tmp/perf3/data` only while that build ran, with a marker file guarding against swaps. BEFORE never opened a clone that AFTER had migrated.
- The renderer phase used a second fresh clone per build. There, the big thread fae77a0b was moved into the scratch project, identically for both builds, so the run guard allowed streaming into it.

**Launch.**
- `env -i`, `HOME=/tmp/perf3/home` and `SHELL=/nonexistent`. `PATH` was the shim directory plus `/usr/bin:/bin:/usr/sbin:/sbin`.
- No inherited `CODER_*` variables. The harness set only `CODER_PROD`, the provider-binary overrides (`/usr/bin/false`, or the fake `claude`), and `CODER_SIMULATE` / `CODER_AGENT_CMD` for streams.
- `NODE_OPTIONS=--require hook.js`. The hook sets `app.setPath("userData", clone)` inside a `Module._load` hook on `electron/main.js`.

**Safety stubs in the hook:**
- stubbed: `sweepOrphanWorktrees`, `createRetentionSweeper`, the wedged-lane watchdog, automations, autodispatch, post-merge, memory consolidation and iOS `recover`;
- the webhook URL is nulled and notifications are off;
- every fs write outside `/tmp` and `/var/folders` throws;
- runner `start*` / `resume*` / `retry*` / `steer*` / `promote*` are refused outside `/tmp/perf3-proj`.

**PATH guard.** The git shim directory is re-prepended:
- after `enrichProcessPath` (BEFORE);
- after `primeProcessPath`, `refreshLoginPath` and `whenPathReady` (AFTER, #1479);
- and by a 500 ms watchdog that never logged a drift.

**Git and gh shims.** The git shim allows read-only subcommands everywhere and writes only inside `/tmp/perf3-proj`; it was smoke-tested to block `git branch` in a real repo. The `gh` shim refuses everything.

**Instrumentation.**
- Main process: PM1's hook, unchanged in what it counts:
  - IPC handle/send wrappers record count, ms and JSON bytes;
  - fs byte accounting by category;
  - timed `Store._serialize` and `_snapshotDirtyShards`;
  - CPU profiles at a 250 µs sampling interval, with instrumentation frames excluded from "JS busy";
  - `monitorEventLoopDelay`;
  - `process.memoryUsage()` after a forced `gc()`.
- Additions for AFTER: the `threads:changed` row-patch encoder is timed; the big-thread open is driven through `thread:select`; and 5 renames isolate `threads:changed`.
- Renderer mode: the same safety, but no payload stringify and no main-process profiler. It was driven over CDP on :9393 with PM2's scripts: `cold.js`, `switch.js`, `stream.js bigopen`, `soak.js`, `ls.js` and `lsw.js`.
- `lib.connect()` refuses to attach unless the port's owning process runs from `/tmp/perf3/{before,after}`. Scripts exit with `process.exit`, never `browser.close()`.

**Streams.**
- Main process: PM1's fake `claude` stream-json (~40 deltas/s, a Bash tool call every 2 s, 32 s) and the simulate provider.
- Renderer: PM2's generic-provider markdown script (~42 k chars per 25 s).
- No network providers ran.

**Repetitions and ordering.**
- 5 warm boots, 3 full scenarios, 5 cold renderer launches and 1 renderer session per build.
- BEFORE and AFTER were interleaved, so background load hit both alike.

**Caveats.**
- **Background load:** this machine was not idle. An unrelated `next-server` dev process held a core the whole time, and the 1-minute load average was 1.6–5.5 during runs; the value is recorded with each run in `/tmp/perf3/out/runs.log`. Interleaving keeps the ratios fair, but absolute times carry that noise.
- **Display:** the panel ran at 4.2 ms frames, so "dropped frames" aren't comparable with PM2's 120 Hz percentages.
- **Fake streams:** they are text-heavy and light on tool cards.

## Leak check

Before the first launch I recorded the following for the 13 git repos referenced by the store's projects (the 14th project is a non-git scratch dir):
- `git for-each-ref`: 745 refs;
- `git worktree list` with each worktree's HEAD and branch: 48 worktrees;
- `recovered/*` branches: none;
- the mtimes of `memory.db`, `memory.db-wal` and `~/.grok/config.toml`.

I re-checked all of it after each of the 33 launches.

**Result: no leak.**
- **Branches and worktrees:** no `recovered/*` branch appeared, and no worktree was added, removed or switched.
- **Guards:** 0 fs writes blocked, 0 runs refused. No git write was attempted outside the scratch repo, and none inside it either. `gh` was refused 64 times.
- **Memory server:** each launch started its own, with its DB under `/tmp/perf3/home`.
- **Grok config:** `~/.grok/config.toml` kept its 09:32 mtime throughout.
- **Live memory DB:** `memory.db` and its WAL did change, but from the live app. The clones' memory servers never pointed at it.

Four checks did show a diff. All were the same branch, `coder/continue-building-443a5b` in `botpoc`, which a live agent thread in the real app was committing to during the session:
- `0b4d74f → 165d3a4` "Fix review findings…", 10:14:50;
- `9f99784` "Quiet hours…" and `b18beaf` "coder-checkpoint: turn 13", 10:23;
- `9e5d381` "Clean clippy…", 10:30;
- `1d9ec048` "README…".

I attributed each one by reflog: every new entry was a plain `commit:` on an existing branch, and the worktree HEAD moved with it. From then on `attribute.sh` (in `/tmp/perf3`) auto-accepted only that pattern. Any new or removed ref, worktree change, `recovered/*`, or HEAD move without a matching commit still halted the run; it was tested against a forged HEAD move. Nothing needed restoring.
