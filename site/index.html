Shared memory

Your agents remember.

Read the memory docs

What one thread learns, the next one knows. Solenta injects a local memory server into every agent session automatically, so decisions and gotchas persist across Claude Code, Codex, Cursor, Kimi, Grok OpenCode and Muse Code. The tenth session on a project is better informed than the first.

  • Injected automatically. When the local server is healthy, every new session gets it. You do not wire it up per agent.
  • Local, and yours to search. HTTP + MCP, localhost-only, bearer-token gated. The Memory tab reads the same SQLite file the agents write, with full-text and vector search.
  • It compounds. Session ten does not re-learn what session one already ruled out.

Orchestration is a sentence, not a config.

Every thread carries tools to drive the other threads. You describe the fan-out in plain language; the agent spawns, supervises and reports back.

  • Fork across providers. The same task on Grok, Kimi and Claude at once, each in its own worktree.
  • Or delegate from the start. An orchestrator thread hands its first prompt to a worker and supervises from there, one setting away from being the default.
  • Async by design. Runs go off in the background; the orchestrator polls and summarizes.
  • Suggested work, one click. Out-of-scope findings land as chips under the transcript, not as a derail.
  • Or pick a fixed pipeline. The Build button runs a known template when the shape is repeatable.

Questions.

How do I run multiple AI coding agents at once?

Open a thread per task in Solenta. Each thread runs the agent CLI you pick (Claude Code, Codex, Cursor, Kimi, Grok, OpenCode or Muse Code) in its own git worktree, so parallel agents never share a working copy. Threads that need you stay up top, and you can fork one task across several providers and keep the best diff. Read the parallel-agent guide.

How do I stop parallel coding agents from stepping on each other?

Give every agent its own git worktree on its own branch. Solenta does that per thread automatically, and a thread only settles green once its verify command exits 0, so "done" means your checks passed, not that the agent said so.

Is Solenta a coding agent?

No. Solenta is the desktop app that runs your coding agents. It drives the agent CLIs you already installed, on your own subscriptions, and adds shared memory, a planboard, worktrees, verify gates and spend caps around them.

Which agents can Solenta run?

Claude Code, Codex, Cursor, Kimi, Grok, OpenCode and Muse Code. Install the CLIs you want to drive and Solenta finds them on your PATH. Permission modes, model overrides and session resume are per provider.

Does my code leave my machine?

Only inside the prompts your chosen agent CLI sends to its provider, same as running that CLI yourself. Solenta adds nothing on top: memory is a local SQLite file, plans are your own GitHub or GitLab issues, and there is no Solenta cloud.

Do I pay Solenta for tokens?

No. Bring your own subscription or API key per provider. Solenta never resells tokens and never sits in the billing path.

What does the planboard need?

A project whose origin is on GitHub or GitLab. GitHub uses a token saved per host in Settings, Git, or your existing GitHub CLI login. GitLab uses glab, including self-hosted hosts with "gitlab" in the name. Other features work without a board.

Is it free?

Yes. MIT licensed, with releases for macOS, Windows and Linux.

You own the tools.

Solenta is MIT licensed and runs on your machine. It drives the agent CLIs you already installed. Plans live in GitHub or GitLab issues. Memory lives in a local SQLite file you can read and export. People who pick tools in 2026 ask who owns them. The honest answer here is you do.

Install in a minute.

Read the getting started docs

Grab the archive for your platform, then install whichever agent CLIs you want to drive. Solenta finds them on your PATH.

macOS

Apple Silicon Detected
Download for macOS
  1. Unzip, then move Solenta.app to /Applications.
  2. Double-click it. The build is signed with a Developer ID and notarized by Apple, so Gatekeeper opens it like any other app.

Apple Silicon only. There is no Intel (x64) build yet.

Windows

x64 Detected
Download for Windows
  1. Unzip somewhere permanent, for example %LOCALAPPDATA%\Solenta.
  2. Run solenta.exe. SmartScreen warns once: More info, then Run anyway.
  3. Pin it to the taskbar yourself if you want it there.

A portable zip, not an installer. No setup wizard, no Start menu entry, and moving the folder later is on you.

Linux

x64 Detected
Download for Linux
  1. tar xzf Solenta-*.tar.gz
  2. ./solenta/solenta
  3. Add a .desktop file yourself if you want it in your launcher.

A tarball for glibc x64 desktops. No .deb, no .rpm, no AppImage yet.
