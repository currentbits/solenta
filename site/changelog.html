Changelog

Every notable change to Solenta, newest first.

0.21.0 2026-09-22

Added

  • New model choices. Select Grok 4.7, Claude Opus 5.5, and GPT-6 Sol, Luna or Terra in their respective providers. Grok 4.7 is now the recommended Grok model. GPT-6 Terra availability depends on your Codex account.
  • Cursor model variants. Grok 4.7 and Claude Opus 5.5 are available with Cursor's supported reasoning levels and Fast variants.
  • Guardrails setting. Turn Solenta's tool, prompt-injection and secret checks on or off in Settings, Advanced. The setting applies across projects; provider permission settings still apply. Restart active agent runs to apply the change everywhere.

Fixed

  • Remote Grok guardrails. SSH and WSL runs now deploy their guardrail hooks on the remote machine, including workflow runs. Remote overlays keep host credentials and local MCP addresses out of the remote configuration, preserve sessions and are cleaned up with the thread.

0.20.0 2026-09-11

Added

  • Import existing CLI sessions. Bring conversations from Codex, Claude Code, Grok, Cursor, OpenCode, Kimi and Muse into Solenta. Import one or all remaining sessions; re-import adds new turns without duplicating the thread.
  • Eject and reclaim. Continue a thread in its provider CLI, then bring outside turns back into Solenta. Eject releases this thread's agent process and copies a resume command; the rest of its crew can keep running.
  • Steer a live turn. Send guidance into a running Claude or Codex turn. The composer has Queue and Steer controls, and Cmd+Shift+Enter steers directly. Your draft stays if delivery fails.
  • Crew integration. The lead's Integration view shows worker readiness, source snapshots and the final destination. Integrate selected workers into the lead, verify the combined result, then merge or open one PR.
  • Recorded worker snapshots. Workers start from the lead's recorded committed revision. See the source branch and SHA separately from the merge destination, and explicitly refresh an idle worker when the lead advances.
  • Local development lanes. Claim a numbered lane with its own branch and port, see its path, preview it in the project checkout and restore afterward. Recycle wedged lanes; optional Spotlight selects the lane to preview.
  • Dev-server isolation. Thread dev servers get separate data, config, cache and temporary directories. Claimed lanes supply a distinct port, and supported local Electron launches get a thread-specific app identity.
  • Command palette. Cmd+K runs commands and jumps to threads or projects. Cmd+P searches project files; Cmd+Shift+F searches their contents and opens a matching line.
  • PR workspace. Create draft PRs with an editable body from the repository template and a markdown preview. View, edit, comment, mark ready, close and merge open PRs in the app.
  • Searchable pull requests. Find PRs by number, title or branch. Load more beyond the initial list and set the per-project list cap in Settings.
  • External MCP pairing. Pair an outside MCP client through Settings, Integrations. Choose project scope, capabilities and expiry, approve launches in Solenta by default, and revoke access at any time.
  • Import from other tools. Preview and selectively copy skills, slash commands, MCP servers, memories and instruction files from Claude Code, Codex and Cursor. Local commands and plugin code have separate trust controls.
  • Plugin slash commands. Enabled Codex and Cursor plugin commands appear in the composer without a manual import, including namespaced commands. Disabled and unlisted cache plugins stay out.
  • Searchable skill library. Search installed skills by name or description and filter by provider and source. Installed skills come first, with catalog, import and MCP tools on secondary views.
  • Memory browsing. Browse older memories beyond the first 20, filter by type, and inspect source and citation details. Config doctor and maintenance tools sit behind the memory list.
  • Saved sidebar views. Save named combinations of project, search, status, provider and tag filters. Rename or update them as your triage changes; views continue matching newly created threads.
  • Recently deleted. Deleting a thread now offers Undo and a seven-day restore window. Restore it from Recently deleted or permanently delete it there.
  • Move threads between projects. Move an idle thread from its menu. Threads with a worktree, an active run or a pending worker binding cannot be moved; old repository bindings are cleared.
  • Better board navigation. Search Planboard by title or issue number and change project scope directly in Activity or Kanban. Back from a thread restores the originating view, filters, focus and scroll position.
  • Automation editing and history. Edit an existing automation in place and open its recent runs. Names, prompts and models can change without creating a second schedule.
  • Transcript pins and quotes. Pin a message with an optional label and jump back to it, even in a long transcript. Quote selected assistant text into the composer with its source attached.
  • Per-turn diffs and restore. Review checkpoint-to-checkpoint changes in unified or split view. Restoring a checkpoint rewinds the conversation along with the files.
  • Files on question answers. Attach supporting files to an individual question answer without mixing them into the composer draft.
  • Browser file and folder attachments. Pick or drop ordinary files and folders in web mode. Folder uploads keep their tree structure, and text-only models can still receive file attachments.
  • First useful conversation. Onboarding guides you through one agent, a project and your first thread, with an empty composer ready for your own prompt. Replay it from Settings.

Performance and memory

  • Responsive transcript search. Content search scans stored transcripts in a background worker instead of parsing every thread into the main process's history cache. A newer query cancels the previous scan.
  • Bounded transcript cache. Previously opened threads use an eight-entry cache with an 8 MiB estimated payload budget. Recent threads still switch immediately; older ones reload on demand. This is a cache limit, not a limit on total app RAM.
  • Smaller store writes. Work logs now live in separate per-thread files. Saving an active thread writes changed logs instead of serializing and rewriting every thread's work log.
  • Faster skill inventory. Skill scans yield to the app, read the install registry once and reuse parsed files across symlink aliases. Opening the catalog no longer repeats a full skill-file scan.
  • Lighter memory diagnostics. The Memory tab loads a small maintenance summary first and requests the full diagnostics when opened, avoiding unnecessary work while browsing entries.
  • Bounded memory export. The optional transcript mirror is capped at 256 pending entries and a 4 MiB estimated payload, including in-flight work. A slow memory server cannot grow the backlog indefinitely; local conversation history stays intact.
  • Agent and server cleanup. Removing a project retires its idle agent sessions. Stop and settle clean up this thread's managed dev server, and app quit terminates detached agents that could otherwise keep consuming resources.

Codex fixes

  • Interactive session transport. Interactive Codex turns now use a private app-server connection, supporting real live steering and command-approval replies while retaining existing session history.
  • Model changes take effect. Switching a resumed thread from Sol to Astra now sends the selected model on the next interactive turn, instead of silently continuing on the original model.
  • Command approvals. Codex command requests show Accept and Deny, plus Accept all when the provider supports it. Commands are read-only on these cards because Codex cannot accept an edited command in its approval reply.
  • Git writes in worktrees. Codex workspace-write includes the checkout's Git metadata and the shared Git paths needed by linked worktrees, fixing blocked git add and git commit operations.
  • Planboard tool availability. Codex's first-party MCP connection binds the actual project ID, so issue tools appear and authorized Planboard writes can run on the host.
  • Writer-lock isolation and recovery. Each isolated Codex home gets its own writer-lock directory. Conflicts identify the owner, release a Solenta-owned holder where possible, preserve the session and avoid a misleading Retry loop.
  • Safe worker wake-ups. Worker notices wait while the Codex session is owned by another run or ejected to a CLI. They no longer repeatedly try to resume the same locked session.
  • Eject model warning. The copied terminal command warns when Codex exec resume would use the session's original model rather than a later picker choice.
  • Native images and text-only models. Supported Codex models receive native image input. Spark rejects image attachments while retaining file and folder attachment controls, and Codex tool-result images are preserved in the transcript.
  • Context usage. The app-server adapter distinguishes the latest context usage from cumulative totals, keeping the context ring from double-counting them.
  • Guardrail startup and hook trust. Codex app-server no longer receives an unsupported exec-only flag. Hook trust is stored in its isolated config so guardrails run without rewriting the user's main Codex config.

Fixed

  • Queued follow-ups. Failed or stopped turns leave the next prompt queued. Failed edits, reorder, removal and retry preserve the draft and queue instead of discarding or duplicating instructions.
  • Retry the right turn. Retrying a failed worker notice sends that notice, not the original human task. Notice provenance is persisted, including backfilled older messages.
  • Stop during startup and quit confirmation. Stop can cancel the first turn while it is still preparing. Quitting asks before stopping active agents, terminals or dev servers, with a setting to control the confirmation.
  • Failed edit-and-resubmit. If the replacement turn cannot start, the previous conversation tail is restored instead of leaving a completed rewind behind.
  • Draft and review persistence. Failed thread-note saves keep the text and offer Retry. Workflow drafts survive selection changes and ask before discard; a successful save followed by a failed refresh no longer creates duplicates on retry. Review acceptance is now saved to disk.
  • Correct project after navigation. Late Planboard, Skills and config-doctor responses cannot apply the previous project's state or write confirmation to the next project.
  • Visible load failures. Activity, Digest, Usage and Fleet distinguish errors from empty results and preserve existing reports where available. PR and Planboard controls recover after rejected requests instead of staying stuck.
  • Settings and automation safety. Opening Settings before data arrives no longer clears untouched spending caps. Repeated Add automation cannot create duplicate schedules, and retention keeps unfinished and quota-wait runs.
  • Crew landing and issue lifecycle. Merge controls name their destination and workers route through the lead's Integration view. Integrating into the lead keeps worker issues open until the combined work lands; changed destinations are refused before writing.
  • Lane ownership. Claimed lanes keep their heartbeat across view changes and local projects, so background work is not mistaken for a wedged lane and recycled.
  • Screenshot and terminal ownership. Delayed screenshots remain attached to their originating thread. Terminal replies from an earlier thread or restart are ignored, and overlapping output is not duplicated.
  • Provider integration details. The Cursor overlay no longer breaks the user's cursor-agent executable. OpenCode receives native file and image attachments, and reclaim handles older OpenCode storage, long Claude/Grok paths and fragmented Kimi replies.
  • MCP command arguments. Quoted executable paths, arguments containing spaces and JSON argument arrays keep their intended boundaries. Malformed quoting keeps the draft and shows an error.
  • Keyboard focus and calmer chrome. Dialogs and popovers keep keyboard focus, Escape dismisses eligible confirmations, and focus returns to the opener. Softer borders and flatter lists reduce visual clutter across the app.
  • Settled crew visibility. Settled workers remain discoverable under an active or pinned parent, so completed crew work does not disappear into another shelf.
  • Planboard comments. Agents can append an issue comment through the host without changing the issue's plan status or closing it.

0.10.0 2026-08-22

Added

  • Light theme. Solenta follows your system light/dark setting, or you can pin either one. The whole interface is tokenised, so every pane, card and diff view comes along.
  • Settings, redesigned. The modal is a proper paned layout instead of one long scroll, so providers, defaults, budgets and data live somewhere you can find them again.
  • The right panel collapses. Fold the agents panel away when you want the transcript full-width; the state persists per window. Interface zoom persists too.
  • Sidebar filters. Narrow the thread list by status and by provider, on top of the existing project scope and search.
  • Let the agent resolve the conflict. A merge conflict gets a one-click button that hands the conflict to an agent instead of dropping you into a manual three-way merge.
  • Check out someone else's PR. Pull an open pull request into its own worktree and start a thread on it, without leaving the app.
  • Outbound webhooks. Fire a webhook when a thread finishes, fails or starts waiting on you. Slack, Discord and ntfy shapes are built in. Opt-in per project.
  • Linear tickets can start a thread. Ticket ingestion is no longer GitHub-only.
  • Per-project setup command. A command that runs automatically whenever a worktree is created, plus named quick actions in the project header, so a fresh worktree is usable without a manual install step.
  • Install-time trust gate. Skills, MCP servers and packages an agent tries to install are scanned before they land, and reported as trusted, caution or blocked. Local and regex-only; no network, no model. Blocked refuses, caution asks.
  • Encrypted credentials. Stored provider keys are encrypted at rest rather than sitting in the plain store file.
  • Jujutsu. Projects on jj are detected and driven through the same worktree and diff paths as git.
  • Cross-thread messages. Threads can hand each other work directly, with delivery you can see, instead of routing everything through the lead.
  • Blast-radius guard. An agent diff that reaches outside the files the task implied is flagged before you review it, and the daily digest reports it.
  • Model and effort pickers, split out. The composer's model row and the reasoning-effort meter are their own controls, and the effort meter follows the model you actually picked.

Fixed

  • Typing in the composer no longer lags. The field is uncontrolled now, so a keystroke stops re-rendering the model rows, pills and slash palette.
  • First paint no longer waits on the whole boot chain, and the store is no longer parsed synchronously on the main process before the window appears.
  • Opening a thousand-message thread windows the transcript instead of mounting all of it into the DOM.
  • A state change no longer ships every thread row to the renderer, and the generic provider stream path is throttled instead of writing the store on every raw chunk.
  • Worktree retention sweeps on a timer, so grace-period crossings are reclaimed while the app is running, and corrupt worktree directories are collectable again instead of being stuck forever.
  • Concurrent grok mcp add writes no longer corrupt the grok config and take every grok run down with it.
  • Every parallel worker gets its own review itinerary, so the shared file stops being a guaranteed merge conflict.
  • The questions modal appears under Fable, Grok and Kimi, not just Claude and Codex.
  • Drag and drop accepts .txt and other plain-text files, not only images.
  • Memory dedup and contradiction detection reuse the embeddings that were already there.
  • Divergence compare is off by default.
  • Worktrees are no longer merged automatically; landing a branch stays an explicit action.
  • A PR opened from a thread shows its link in the related thread again.
  • Image stores under userData are cleaned up with the threads that made them.
  • CI runs the renderer build, so a CSS parse error fails the gate instead of reaching a release.

0.9.0 2026-08-21

Added

  • First-run onboarding. A welcome wizard on first launch: check which agent CLIs are installed and how to get the missing ones, add a project and set the defaults, then a short tour of the app. Replay it any time from Settings → Show welcome tour.
  • Worktrees clean themselves up. Checkouts created by a fork or handoff, and worktrees belonging to archived threads, no longer take up the per-project keep-N buffer. Ten abandoned worker checkouts was several gigabytes nobody would ever open again. They are collected once the thread goes quiet, with a three-day grace period if they still hold unlanded commits. The branch always survives; only the directory goes.
  • Planboard issues close themselves. When a thread's work lands, the issue it was tracking moves to done and closes, instead of sitting open behind a merged branch.

Fixed

  • Removing a project works again. Removal reclaims the attached worktrees rather than refusing because archived threads still point at them, a tree with uncommitted work is left on disk for the GC panel instead of being force-deleted under you, and a removal that does fail now says why.
  • Clicking through threads no longer rewrites the whole store. Selecting a thread stamped a timestamp that scheduled a full rewrite of the entire store file; the stamp now rides the next real write. Boot's backup snapshot is a copy-on-write clone instead of a byte copy, and the write cadence under sustained streaming is far less aggressive.
  • IPC channels are generated from a single list, so a channel can no longer be wired up in the app but missing from the packaged build.

0.8.0 2026-08-20

Added

  • Flat sidebar. Thread rows are a status dot, a title and an age; no project group headers. Cards carry their project slug; a scope filter still limits the list to one repo. Pinned threads sit in their own block at the top; snoozed and settled have their own shelves; archived sit at the settled tail. Spaces are gone.
  • Sidebar polish. Right-click a card for the native thread-actions menu. Subagents nest under the thread that spawned them, idle stopped fork workers drop off the list, and Delegating / Orchestrating / Working statuses are back. Project icons are picked up from the repo's favicon or app icon.
  • Git in the thread. The worktree diff is a full-height Git tab in the thread header, not a card in the right-hand panel. Environment's Open Git, the next-action Commit, and /review all open it there.
  • Ask mode. Read-only questions about the repo, answered from the code index and shared memory. No worktree, no tools, and no spend against the daily budget. Start work turns it into a normal thread.
  • Spec dispatch. Once tasks.md is approved, the checkboxes are a DAG. Dispatch forks a worker per unblocked task; Converge re-reads the artifacts and the repo and appends missing checkboxes.
  • Divergence compare. When two runs of the same task exist, Environment can pair their tool steps and name the first mismatch. Opt-in per thread.
  • /btw. Ask a side question on the same thread without interrupting the live run. ⌥Enter on a plain draft does the same.
  • Slash palette extras. The / menu lists the underlying CLI's own skills and custom commands alongside Solenta's verbs.
  • Suggested-work chips. Out-of-scope findings become one-click new threads (or a planboard issue) instead of derailing the current run.
  • Host thread tools. Agents can archive, settle, stop, rename, merge and open a PR on threads, not just list, fork, send and poll.
  • Quota-wait. A provider usage-limit with a reset clock parks the thread and resumes the same prompt when the quota comes back, instead of failing.
  • Review bottleneck. Create PR refuses a diff larger than the PR size cap (default 400 lines) and offers to split the branch into a stack. Planboard shows review load.
  • Perception gap. After a thread finishes, a one-tap card asks how much time it felt like it saved; fleet analytics compares that to wall-clock.
  • Provenance chips. Assistant claims in the transcript are labelled by what they actually cited (repo paths, shared memory, GitHub) or tagged model prior knowledge.
  • Config doctor. The Memory tab lints AGENTS.md / CLAUDE.md against shared memory, and can write those files from it.
  • Vibe Kanban import. Settings → Your data reads a local VK database and turns cards into threads.
  • Edit before approve. A permission prompt that is a shell command is an editable field; approving sends the edited command, not the original.
  • Nightly, side by side. Nightly ships as Solenta Nightly with its own bundle identifier, so prod and nightly install next to each other.

Fixed

  • Boot no longer walks du over every worktree.
  • Worktree GC actually enforces per-project retention, so stale archived worktrees get cleaned up instead of accumulating.
  • The Electron main process, renderer re-renders and polling, and the memory-server query and write path are snappier.
  • The thread view re-pins when content grows after paint, and autoscroll no longer unsticks on a thread switch.
  • error_during_execution / cancelled is no longer shown as a raw Run error.
  • Grok runs in asking modes no longer look user-stopped.
  • Usage view: Kimi is visible again, and Claude token counts include cache tokens.
  • You can add a folder that is not a git repository yet; the destination path is typeable and browsable. Projects can be removed again.
  • A renderer from an older main-process build hard-blocks until you reload.
  • Planboard, Kanban and Activity follow the sidebar's project scope.
  • The new-thread dropdown is fully visible.

0.7.0 2026-08-18

Added

  • Teach mode. A thread can run as a tutor: hints, not solutions, across all five providers. Autonomy steps up as reviews pass (Hints, then Review, then Pair) and permission modes stay gated to the current rung.
  • Review itinerary. Every agent diff gets a risk-ranked read order: CI and config first, then reuse, the critical path, tests, and the rest, chunked by area instead of alphabetically.
  • Thread snooze. Hide a thread until this evening, tomorrow, next week, or a custom time. A thread that raises its hand (blocked on you, or a fresh failure) wakes early. Settle-on-merge can archive a thread the moment its PR lands. A Woke pill marks what came back.
  • Next git action. One header button that always names the next step: commit, push, open a PR, watch checks, or merge. Create PR is available on an unpublished worktree without a prior Push.
  • Subagent model pool. Describe candidate models once in Settings; the lead picks per spawn instead of every worker inheriting the same default.
  • Orchestration commands. Type /handoff, /advisor or /committee in the composer to plan here and implement elsewhere, get a second opinion, or have two contrasting models converge on a root cause. The / palette now lists the CLI verbs too, not only the orchestration ones.
  • Drop images and folders on the thread. The whole transcript is a drop target, not just the composer strip, and Finder folders keep their absolute paths.
  • Memory strategies. Alongside facts, memory now stores distilled how we work here entries, and citations on a fact are checked against the current worktree before they are injected.

0.5.0 2026-08-16

Added

  • Orchestrator threads. A new thread mode hands the thread's first prompt straight to a worker in its own worktree, and the thread itself stays back to supervise. Pick it from the caret next to + in the sidebar, which now offers all three modes: worktree, orchestrator, and plain (straight in your checkout).

  • User-registered MCP servers no longer get blanket tool auto-approval in headless Claude runs.
  • Saving an image from a thread is confined to that thread's directory, closing a path traversal.

Fixed

  • The main process survives an unhandled rejection instead of taking the app down with it.
  • Merging a worktree no longer refuses on a dirty project checkout (it auto-stashes), and untracked files stopped blocking merges outright.

0.1.0 2026-08-13

First public release.

  • Threads: one agent session per thread, with sticky permission modes, model override, reasoning effort, fork and hand-off, and Best of N across providers.
  • Worktrees and PRs: per-thread branches, live diff, checkpoints with restore, PR checks as badges, and one-click squash merge.

  • Web mode: the full UI served over HTTP and WebSocket behind a session token.
  • SSH remote projects: run agents on another machine over key-based SSH.
