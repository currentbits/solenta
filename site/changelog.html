Changelog

Every notable change to Solenta, newest first.

Unreleased

Added

  • Agent-created pull requests. An agent can open a PR from its own worktree branch, and asks for your approval through an in-app permission prompt instead of stalling in the background.
  • Worktree threads. A thread can get its own git worktree the moment it is created, so the agent starts on an isolated branch and never touches your checkout.
  • Project create flow. Add a project from inside the app with a native directory picker, instead of pointing Solenta at a path by hand.
  • Edit projects after the fact. Rename a project or change its SSH remote host and path from a settings modal, without removing and re-adding it.
  • Model picker for automations. Scheduled runs can pin a specific model per automation, the same way threads can.
  • Linux and Windows builds. Releases now ship linux-x64 and win32-x64 archives alongside the macOS build.
  • This website. A landing page, full docs, and this changelog.

Fixed

  • The final answer of a run now streams as its own message below the tool calls, instead of being interleaved with them.
  • Tool cards in the run timeline no longer collapse into thin bars when the timeline is crowded.
  • A first-boot data migration could run during short-lived probe boots and lose user data; migrations now only run in real app launches.
  • Creating a project from a fresh install failed because two IPC endpoints were missing from the preload bridge.

0.1.0 2026-08-13

First public release.

  • Threads: one agent session per thread, with sticky permission modes, model override, reasoning effort, fork and hand-off, and Best of N across providers.
  • Worktrees and PRs: per-thread branches, live diff, checkpoints with restore, PR checks as badges, and one-click squash merge.
  • Build workflows: multi-phase templates (seed, analyze, verify, judge, synthesize) with per-phase fan-out.
  • Orchestration: every session gets thread tools so any agent can list, fork, drive and poll the others.
  • Shared memory: a supervised local memory server injected into every session.
  • Automations: scheduled prompts with pause and run-now, surfaced as ordinary threads.
  • Spend guardrails: a daily budget that blocks new runs once reached, with per-thread token and cost readouts.
  • Web mode: the full UI served over HTTP and WebSocket behind a session token.
  • SSH remote projects: run agents on another machine over key-based SSH.
