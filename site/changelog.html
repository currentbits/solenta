Changelog

Every notable change to Solenta, newest first.

0.5.0 2026-08-16

Added

  • Orchestrator threads. A new thread mode hands the thread's first prompt straight to a worker in its own worktree, and the thread itself stays back to supervise. Pick it from the caret next to + in the sidebar, which now offers all three modes: worktree, orchestrator, and plain (straight in your checkout).
  • Delegate new threads by default. A Settings toggle makes every new thread an orchestrator, so fan-out is the default rather than something you remember to choose.
  • Start task picks the mode. Starting work from a Planboard card lets you choose worktree, orchestrator or plain instead of always following the app default.
  • Delegating status. A thread whose workers are still running reads Delegating and stays in Working on the Kanban, instead of claiming it is done while its crew is mid-run.
  • Per-orchestration budget ceiling. A second cap in Settings, alongside the daily budget, bounds what one fan-out can spend. Empty means no cap.

Security

  • MCP bearer tokens are written 0600, revoked on shutdown, and kept out of the Codex command line, so they no longer leak into user config or the process table.
  • Adopting a running memory server now requires proof the process knows the shared secret, so nothing squatting on the port can be handed your memory traffic.
  • User-registered MCP servers no longer get blanket tool auto-approval in headless Claude runs.
  • Saving an image from a thread is confined to that thread's directory, closing a path traversal.

Fixed

  • The main process survives an unhandled rejection instead of taking the app down with it.
  • Merging a worktree no longer refuses on a dirty project checkout — it auto-stashes — and untracked files stopped blocking merges outright.
  • Run now failures on an automation surface on the row instead of vanishing.

0.4.0 2026-08-16

Added

  • Planboard. One project's plan as its GitHub issues in Todo / In progress / Done, with a per-project selector. Agents write to it with nothing but gh, their todo list is mirrored as live plan steps, and you can start a thread straight from a Todo card.
  • Plan overview card. When an agent writes a plan, it is pinned in the thread panel instead of scrolling away, and plans in permission prompts render as a plan rather than a wall of text.
  • Images and folders in the composer. Attach them to a message, see images agents produce inline, and click any image to view it full size.
  • Type-ahead during a run. The composer stays live while an agent works and queues your next message instead of dropping it.
  • Desktop notification controls. A global toggle in Settings and a per-thread mute.
  • Cascade stop. Stopping an orchestrator stops its crew, and workers run in their own git worktree so they never collide.
  • Better hand-offs. A fork now carries a tail digest of the source thread rather than one truncated reply, and a thread shows what it is waiting on — including workers blocked on a permission prompt, and orchestrator wake-ups held back by the budget.
  • Question prompts as a picker. An agent asking you to choose renders as options with keyboard shortcuts, and Agent-tool subagents appear in the Agents panel.
  • Denser sidebar. Smaller thread cards, sticky group headers, and a per-group overflow cap so a busy day stays readable.
  • Safer auto-update. Installing is gated behind a click and the downloaded asset's digest is verified first.

Fixed

  • Streaming no longer re-renders all three panes on every tick, the Agents panel stopped re-querying every thread's messages per event, thread tails stream over IPC instead of the whole transcript, and @-mention search caches its file list.
  • Transcripts are capped per thread and the store flushes off the event loop, so a long-running thread no longer rewrites megabytes on every token.
  • Every synchronous git and ssh call on the main process is bounded by a timeout, so a hung remote cannot freeze the window.
  • A web-server port conflict no longer kills app boot with no window and no error.
  • Squash-merge conflicts get a resolution path instead of a raw git dump.
  • The memory server exits when its parent does, so an ungraceful quit stops leaving orphans behind.
  • React error boundaries around the three main panes turn a render bug into one broken pane instead of a blank app.
  • Idle agent CLIs are retired when a thread settles or is archived, and kept-alive Claude processes are capped at three.
  • A Claude turn no longer fails on a timer while the CLI is still working.
  • Switching threads no longer shows the previous transcript under the new selection, and a failed thread load offers a retry.
  • A thread can no longer spawn workers into another project's repository.
  • Update-check failures are surfaced instead of leaving a stale “Up to date”.
  • Local Servers hides ephemeral-port listeners that are not web servers.

0.3.0 2026-08-14

Added

  • Grok 4.6. The Grok picker now offers 4.6 (the CLI default) alongside 4.5, and extra-high reasoning effort.

Fixed

  • Orchestration worker threads now archive themselves once their run lands done, instead of piling up in the sidebar.
  • Finished workers no longer show up in the Agents Team list, so the list reflects who is still working.

0.2.1 2026-08-14

Includes 0.2.0, released the same morning.

Added

  • Auto-updates. Prod and nightly channels, with a channel picker and a manual check-for-updates in Settings.
  • Agent-created pull requests. An agent can open a PR from its own worktree branch, and asks for your approval through an in-app permission prompt instead of stalling in the background.
  • Worktree threads. A thread can get its own git worktree the moment it is created, so the agent starts on an isolated branch and never touches your checkout.
  • Project create flow. Add a project from inside the app with a native directory picker, instead of pointing Solenta at a path by hand.
  • Edit projects after the fact. Rename a project or change its SSH remote host and path from a settings modal, without removing and re-adding it.
  • Model picker for automations. Scheduled runs can pin a specific model per automation, the same way threads can.
  • Settled tail actions. Settle all from the collapsed tail bar, and Clear to bulk-archive with an undo toast.
  • Waiting badge. A thread shows it is blocked on a permission prompt rather than looking idle.
  • Worker threads in the sidebar. Forked orchestration workers nest under the thread that spawned them.
  • Linux and Windows builds. Releases now ship linux-x64 and win32-x64 archives alongside the macOS build.
  • This website. A landing page, full docs, and this changelog.

Fixed

  • The final answer of a run now streams as its own message below the tool calls, instead of being interleaved with them.
  • Tool cards in the run timeline no longer collapse into thin bars when the timeline is crowded.
  • Headless Grok runs died on the first gated tool; asking modes now map to auto and run errors surface instead of vanishing.
  • The Claude CLI stays alive across turns, so background tasks survive a settle.
  • The New-thread dropdown stays inside the app window instead of opening off-screen.
  • Composer drafts are kept per thread instead of carrying text across switches.
  • The Memory tab is scoped by project path, not display slug.
  • A first-boot data migration could run during short-lived probe boots and lose user data; migrations now only run in real app launches.
  • Creating a project from a fresh install failed because two IPC endpoints were missing from the preload bridge.

0.1.0 2026-08-13

First public release.

  • Threads: one agent session per thread, with sticky permission modes, model override, reasoning effort, fork and hand-off, and Best of N across providers.
  • Worktrees and PRs: per-thread branches, live diff, checkpoints with restore, PR checks as badges, and one-click squash merge.
  • Build workflows: multi-phase templates (seed, analyze, verify, judge, synthesize) with per-phase fan-out.
  • Orchestration: every session gets thread tools so any agent can list, fork, drive and poll the others.
  • Shared memory: a supervised local memory server injected into every session.
  • Automations: scheduled prompts with pause and run-now, surfaced as ordinary threads.
  • Spend guardrails: a daily budget that blocks new runs once reached, with per-thread token and cost readouts.
  • Web mode: the full UI served over HTTP and WebSocket behind a session token.
  • SSH remote projects: run agents on another machine over key-based SSH.
